公式カード **1586枚** を採録。日本の食品 **2958件**。特殊能力 **100種**。カードはすべて英語と日本語の2言語。テストカバレッジ **100%**。バーコードバトラーII用のカードは実機で確認済み。

---

バーコードバトラーの本体と、ファミコン、スーパーファミコン、ゲームボーイのいくつかのゲームは、バーコードの数字だけからキャラクターやアイテム、効果を決めます。maeyomi はその計算を逆向きに解きます。防御力2400の「ぼうぐ」がほしいと指定すれば、本体がそう読むバーコードを求めて印刷します。前読み（まえよみ）は、バーコードバトラーでキャラクターになる読み方の本体側の呼び名で、このプログラムの名前でもあります。

対応しているのは単体の本体3台と30本のゲームです。読み取り部がカートリッジにあるファミコンのデータック用ゲーム6本、本体につないだバーコードバトラーIIからコードを受け取るファミコンとスーパーファミコンのゲーム13本、ナムコのバーコードボーイで読むゲームボーイのゲーム5本、専用のリーダーが付いたゲームボーイのゲーム「バーコード対戦バーディガン」、セガの HCV-1000 で Code 39 のカードを読むニンテンドーDSのゲーム「カードであそぶ! はじめてのDS」、「オシャレ魔女 ラブandベリー DSコレクション」、「甲虫王者ムシキング スーパーコレクション」、そしてマイクにつなぐスキャナーで Code 128 のカードを読むニンテンドーDSのゲーム「ワンタメ ミュージックチャンネル どこでもスタイル」と「流星のロックマン ドラゴン」です。どれについても、バーコードが分かっている発売済みのカード、注文どおりに作るカード、そして本体が読むいちばん強いか役に立つカードであるチートカードを印刷できます。

どのゲームの規則も、ゲーム自身のプログラムから読み取り、MAME で動くゲームで確かめています。生成したバーコードは紙に出る前に必ずもう一度デコーダに通します。印刷したページはラスタライズしてバーコードリーダーで読み直します。印刷したカードは実機のバーコードバトラーIIに通して確認しました。

## インストール

```bash
brew tap gufranco/maeyomi https://github.com/gufranco/maeyomi
brew install gufranco/maeyomi/maeyomi
```

tap はこのリポジトリそのものです。リポジトリ名が `homebrew-maeyomi` ではないため Homebrew には URL を明示します。こうしておくと formula とソースとリリースが同じ場所に揃い、別リポジトリに分かれて食い違うことがありません。

インストールすると Python 3.14 が入り、コミット済みのロックファイルから独立した環境を作ります。テストが通ったのと同じバージョンが入り、手元の Python には何も足しません。

チェックアウトから使う場合は `uv sync --extra ui` を実行し、以下のコマンドの先頭に `uv run` を付けてください。

ニンテンドーDSの5本のゲームは、買い物のバーコードではなく Code 39 か Code 128 を読むリーダーで自分のカードだけを読むので、画面はそれに合わせて変わります。ランダムなシートはゲーム自身の一覧から選び、バトルラッシュも同じです。数値の範囲は持たず、カードに数値がないゲームでも範囲の欄は隠れます。**スーパーマーケット** は棚の商品がどれもカードにならないことを、「チート」はカードに数値がないゲームにチートカードがない理由を示し、どちらも「ほんものの カード」と「カード 1まい」へ案内します。「バーコードを よむ」は、カードのバーの下に書いてあるコードを入力するように案内します。

## コマンドラインから

上のタブは、すべてコマンドとしても用意されています。どのコマンドにも `--device` で[対応している本体とゲーム](#対応している本体とゲーム)の表の名前を付けられます。付けなければバーコードバトラーII用のカードになり、下の例もそうです。

ランダムなカード24枚。A4に9枚ずつ並び、シードを指定すれば何度でも同じ結果になります。

```bash
maeyomi random --count 24 --hp 1000-10000 --st 100-3000 --df 100-3000 \
    --seed 1234 --output cards.pdf
```

数値を指定して1枚だけ作る場合。

```bash
maeyomi generate --name "Fire Knight" \
    --hp 5000 --attack 1800 --defense 1200 \
    --race human --class warrior --ability 17 \
    --output fire-knight.pdf
```

指定した値と実際にできた値を並べて表示するので、違いが出たカードが黙って通ることはありません。

```
Field    Requested       Generated       Difference
---------------------------------------------------
HP       5000            5000
ST       1800            1800
DF       1200            1200
PP       any             5
MP       any             0
Race     human           human
Job      -               0
Class    warrior         warrior
Speed    -               0
Ability  17              17
```

本体と同じ読み方でバーコードを読むには次のようにします。

```bash
maeyomi decode 0401207237501
```

本体は特殊能力を属性名ではなく番号で持っています。一覧はこちらです。

```bash
maeyomi abilities
```

アイテムも同じように作れます。武器は攻撃だけ、防具は防御だけ、おたすけアイテムは体力・薬草・MPのうち1つだけを持ちます。薬草とMPは0から99までの個数です。

```bash
maeyomi generate --name "Herb Pouch" --race support_item --herbs 99 \
    --output herbs.pdf
```

数値のオプションは、正確な値・範囲・上下限のいずれでも指定できます。`5000`、`5000-6000`、`>=1500`、`<=3000` のように書きます。`--images png` を付けると PDF と一緒にページ画像も書き出します。

指定どおりのカードが作れない場合、`generate` はどの項目が原因かを示して何も書き出しません。`--nearest` を付けると、到達できる範囲でもっとも近いカードを作ります。

```bash
maeyomi generate --hp 20900 --st 11000 --df 10000 \
    --race mechanical --nearest --output golem.pdf
```

```
closest card differs by 100 across the requested stats
  df: requested 10000, produced 9900
```

ここでいう距離は、指定した項目に限った体力・攻撃・防御の差の合計です（表示上の単位）。種族・職業・特殊能力・素早さは近似しません。人間がほしいという指定に鳥で答えても仕方がないので、それらが原因で作れない場合は作れないまま返します。

`--back-read` を付けると、本体が後読み（うしろよみ）で読むカードになります。上限は前読みより低く、体力は99900に対して49900までです。4桁が能力値と特殊能力をまとめて決めるため、作れる組み合わせはかなり限られます。

## 本体とゲーム

### バーコードバトラーII

バーコードバトラーIIは既定の本体です。バーコードの数字だけからキャラクターやアイテムを決め、表から通すと前読み、逆向きに通すと後読みで読みます。

#### 本体が保持している値

出典は [barcodebattler.net](https://barcodebattler.net/) です。数値はデコーダに直接書き込むのではなく、計算の結果として再現しています。

| 項目 | 前読み | 後読み |
|---|---|---|
| 体力 | 0 〜 99900 | 0 〜 49900 |
| 攻撃 | 0 〜 19900 | 0 〜 11900 |
| 防御 | 0 〜 19900 | 0 〜 9900 |
| 特殊能力 | 00 〜 99 | 00 〜 29 |

種族0から4はキャラクターで、順にメカ・動物・海の生き物・鳥・人間です。種族5から9はアイテムです。職業の数字0から6は戦士、7から9は魔法使いです。値は100単位で保持されるため、能力値は必ず100の倍数になります。

指定できる範囲を狭める制約が2つあります。どちらかに当たった指定は、理由を示して断ります。黙って別の値に置き換えることはありません。

- 体力が19900を超えるキャラクターには、公開されている前読みマーカーが必要で、3桁目が9に固定されます。そのカードの体力は必ず900で終わり、素早さは必ず5になります。
- 種族0・1・2は体力20000を超えると攻撃と防御が書き換えられます。そのため、その大きさでは任意の組み合わせに到達できるわけではありません。その中には、表示より大きい、最大24600の攻撃や防御で戦うバーコードもあり、カードにはその値も印刷します。

#### しくみ

```
指定した値 -> 桁の配置 -> バーコード -> デコーダ -> 照合 -> 採用
```

前読みは決まった桁の並びを各項目に割り当てているので、逆算は探索ではなく配置です。すべて指定された要求は各桁を一意に決め、チェックディジットを計算すれば候補は1つになります。総当たりなら10^12通りを歩くところです。それでも候補は必ずデコーダに通し、どれか1項目でも食い違えば捨てます。

後読みは一対一ではありません。4桁が体力・攻撃・防御・特殊能力をまとめて決め、種族はチェックディジットの位置にあるため配置できず、空いた桁を調整して合わせにいく必要があります。到達できる集合は小さく、すべて列挙できます。10000通りの桁の組み合わせから、体力の百の位が半分になる関係で5000通りの能力値の組が生まれます。

バーコードはモジュール幅を明示してベクターで描きます。既定値は EAN の標準値である0.33mmです。ラスタライズしたバーコードをレイアウトに合わせて拡大縮小すると、モジュールの幅が不均等に丸められて読めなくなります。これは数字の文字列をいくらテストしても見つかりません。

### 初代バーコードバトラー

1991年の初代バーコードバトラーは、同じ数字を独自の方法で読みます。キャラクターはすべて戦士で、体力は19900、攻撃と防御は9900が上限です。2桁の番号は別の表の特殊能力で、IIでは攻撃2倍になる18が、初代では主人公フラグになります。`decode`・`generate`・`cheat` に `--device bb1` を付けると、初代用のカードを作れます。初代用のデコーダは、初代向けの4つのカードリストに載っている113枚を再現します。初代の実機ではまだ1枚も読み取っておらず、初代用のシートにはそのことを記しています。

### バーコードバトラーII ダブル

### データックのゲーム

データックはバンダイのファミコン用バーコードリーダーで、ゲームごとの小さなカートリッジを差し込んで使います。

### バーコードボーイで読むゲームボーイのゲーム

### カードであそぶ! はじめてのDS

セガが2007年に出したニンテンドーDSのゲーム「カードであそぶ! はじめてのDS」は、2つめのスロットにさすセガのカードリーダー HCV-1000 で Code 39 のカードを読み、`--device cardasobu` を付けるとこのゲーム用のカードを作れます。カードはそれぞれ1つのかなを教え、もう1枚はカードさがしをはじめます。ゲームはカードの文字の最初の10文字が自分の表のどれかと一致し、残りが V01 のときにカードを受け付けるので、カードに数値はなく、チートカードもありません。`--character` で、かなの順番、英語の名前、日本語の名前のどれかで46枚から1枚を選びます。カードの Code 39 は、カードに収まるいちばん太い 0.22 mm のモジュールで印刷します。HCV-1000 を持つエミュレータはほかにないので、ゲームは決まったコミットの GBE+ に、カードを通す操作を台本どおりに再生する小さなパッチを当てて動かしています。46枚すべてを受け付け、バージョン違い、どのカードにもない文字、表が「か」のために空けている枠は受け付けません。

### オシャレ魔女 ラブandベリー DSコレクション

### 甲虫王者ムシキング スーパーコレクション

セガが2007年に出したニンテンドーDSのゲーム「甲虫王者ムシキング スーパーコレクション」は、HCV-1000 でムシキングのアーケードカードを読み、`--device mushiking` を付けるとこのゲーム用のカードを作れます。ゲームはカードを13文字のコードの一覧として持っていて、5つは専用のファイルに、2つはプログラムの中にあり、コードが一致した最初のカードを受け付けます。FFF で終わるコードは最初の10文字で一致し、最後の3文字でバージョンが決まります。MKF、RH5、NCI、BTF、KWG はそれぞれ1つのバージョンを示し、それ以外はカード自身のものです。ここでは535枚をそれぞれのコードで印刷します。ムシカードとパートナーカードはそこに描かれたムシやキャラクターの名前で、わざカード、ライセンスカード、とくべつカードは番号で呼びます。`--character` で名前、コード、番号のどれかで選びます。カードに数値はないので、チートカードはありません。一覧はゲームから読み取り、ゲーム自身のくらべるルーチンを Unicorn エンジンで動かして確かめています。すべてのカード、FFF で終わるカードのバージョン、どのカードにもないコードを含む1347件のコードすべてで一致しています。

### ワンタメ ミュージックチャンネル どこでもスタイル

カプコンが2007年に出したニンテンドーDSのゲーム「ワンタメ ミュージックチャンネル どこでもスタイル」は、2つめのスロットに付けてマイク端子でDSにつなぐスキャナーでワンタメのアーケードカードを読み、`--device wantame` を付けるとこのゲーム用のカードを作れます。スキャナーは12桁の Code 128 のバーコードを読み、6組の2桁の数字を音にして送り、そのあとに Code 128 のチェック値を送ります。ゲームはチェック値を確かめ、2組めの数字でカードの表を選び、6組すべてが表のどれかと一致したときだけカードを受け付けます。そのため注文どおりに作るカードもチートカードもありません。ここでは235枚をそれぞれのコードで印刷します。いぬ、ふく、アクセサリ、エフェクトのカードで、ゲームの名前と、カードに印刷された番号が入ります。もう1枚のふく S36 は、ゲームが見つけても、読み取るどの場面でも専用のメッセージを出して何もくれないので、印刷しません。`--character` で名前、コード、番号のどれかで選びます。表はゲームのプログラムから読み取り、ゲーム自身のチェック値の確認、カードの確認、カードの検索を Unicorn エンジンで動かして確かめています。すべてのカードとどのカードにもないコードを含む390件のコードすべてで一致し、まちがったチェック値で送ったものはすべて受け付けませんでした。

### 流星のロックマン ドラゴン

カプコンが2006年に出したニンテンドーDSのゲーム「流星のロックマン ドラゴン」は、2つめのスロットに付けてマイク端子でDSにつなぐ、画面付きのおもちゃ「ウェーブスキャナー」でウェーブカードを読み、`--device rockman` を付けるとこのゲーム用のカードを作れます。ウェーブカードには 040000 で始まる12桁の Code 128 のバーコードがあり、ウェーブスキャナーはそのうち最後の3組だけを、それぞれ63までの数として、定数のあとチェック値の前に送ります。ここでは211枚をそれぞれのコードで印刷します。スタンダード、メガ、ギガ、キャラクターのカードで、GBE+ の資料のとおりの名前と番号が入ります。3枚のキャラクターカードはバトルカードと同じコードなので、そのカードと並べて名前を出します。`--character` で名前、コード、S-001 のようなカード番号、一覧の番号のどれかで選びます。カードに数値はないので、チートカードはありません。一覧とスキャナーのしくみは GBE+ の資料から取っていて、ほかのすべての本体と違い、ゲーム自身の読み方ではまだ確かめていません。ゲームのプログラムの中で、スキャナーを読むルーチンが見つかっていないためです。

## 動作確認

`maeyomi doctor` は、この環境で本体が読めるカードを印刷できるかどうかを確認し、各項目が何を見たかを表示します。答えの分かっているバーコードを読み、シンボルを描いて PDF から読み直し、日本語フォントが解決できているかを確かめ、配色をコントラストと色覚の基準で測り直し、2種類のカード一覧を数え、動かしている処理系・端末が日本語を表示できるか・空き容量を報告します。本当に問題があるときだけ終了コードが0以外になります。どちらの入れ方をした場合でも最初に実行してください。フォントが解決できていないと、印刷したカードの文字が空白になって初めて分かります。

## 印刷

必ず等倍（100%）で印刷してください。「用紙に合わせる」「縮小して全体を印刷」などの倍率指定はすべて切ってください。拡大縮小されたページは見た目には正しいまま読めなくなります。スキャナが測っているのはモジュールの幅だからです。

カードは縦向き、63.5×88.9mmのポーカーサイズで、A4に9枚並びます。カードスリーブや裁断機が想定している寸法です。これはこのプロジェクトが選んだ寸法です。エポック社は自社カードの寸法を公表しておらず、収集家のページにもオークションの出品にも wiki にも記録がありません。寸法は [`layout.py`](src/maeyomi/rendering/layout.py) の `CARD_WIDTH_MM` と `CARD_HEIGHT_MM` にあり、この2つを変えれば他もすべて追従します。グリッド・間隔・各種マーク・収まりの検査は、いずれもこの2つから導かれています。

シートは印刷所が求める条件に従います。

| 項目 | 値 | 理由 |
|---|---|---|
| 塗り足し | シートで1.5mm、`--print-shop` では3mm | 裁断が少しずれてもインクが残る |
| カード間の間隔 | 4mm（塗り足しの2倍） | 隣と共有せず、カードごとに独立した裁断線になる |
| 安全領域 | 仕上がり線から4mm | 読む必要のあるものが裁ち落とされる位置に来ない |
| トンボ | 塗り足しの端から始まる角のみの目印 | 裁断の基準になり、カードの上を線が横切らない |
| モジュール幅 | 0.330mm | GS1 EAN-13 の標準値 |
| バーの高さ | 22.85mm | GS1 の標準値であり、手で通すときの許容範囲そのもの |

`--print-shop` を付けると、同じカードをもう一つの形で書き出します。1ページに1枚、ページサイズはカードに3mmの塗り足しを加えた大きさ、定規もマークもなし。これは商業印刷所の入稿指定そのものです。

各シートの下部には100mmの定規がセンチ単位の目盛付きで入り、カードの上には各バーコードの正しい幅を英語と日本語で示す一行が入ります。最初の1枚を印刷したら定規を当ててください。短ければプリンタがページを縮小しています。設定を直してもう一度印刷してください。どちらの帯もカードの並びの外側にあるので、裁断すれば一緒に切り落とされます。

## 手元のバーコードを読む

`maeyomi decode 4901085061169` は、任意のバーコードを本体がどう読むかを表示します。`-o card.pdf --name "トマトソース"` を付ければカードも印刷します。ウェブ画面の「バーコードを よむ」も同じで、バーの下に印刷されている数字を入力すると、カードの種類・3つの数値・特殊能力・前読みと後読みのどちらで読まれるかが表示され、そのまま印刷できます。

`maeyomi kinds` は本体が扱うカードの種類を、両方の言語でそれぞれの役割とともに一覧表示します。

実際、当時はこうして遊ばれていました。商品のバーコードはどれもカードになるので、トマトソースの瓶はキャラクターに、スナック菓子の袋は武器になります。日本の商品コードも他と同じように扱えます。`4902102072618`、お茶のボトルは防御力2400の「ぼうぐ」です。

## スーパーマーケット

`maeyomi products --search 茶` は該当する日本の食品を一覧表示し、`--count 9 --seed 3` はランダムに選び、`-o shopping.pdf` で印刷します。ウェブ画面の **スーパーマーケット** も同じで、**おまかせ** ボタンが付いています。トマトソース対ラーメンも立派な勝負です。

この棚は [Open Food Facts](https://world.openfoodfacts.org/) から選んだ部分集合です。日本の企業に割り当てられたバーコード、つまり45と49で始まるものに限り、日本語表記の名前を持ち、デコーダが受け付けるものだけを残しました。元のデータは Open Database License で公開されており、この部分集合も同じ条件を引き継ぎます。帰属は **出典** に記しています。カード上の数値は一切そちらから来ていません。すべてこのプロジェクトのデコーダがバーコードから読み取ったものです。名前が間違っていても、冗談が一つ滑るだけで済みます。

ウェブ画面の `maeyomi decode <barcode>` は Open Food Facts に商品名も問い合わせ、分かれば名前欄に入れます。これは便宜上の機能で、問い合わせが失敗してもカードの内容は変わりません。

## 実在のカード

`maeyomi official --list` はエポック社、バンダイ、ナムコが発売した46のカードリストと、それぞれ何枚印刷できるか、どの本体向けのリストかを表示します。`maeyomi official --set candy -o candy.pdf` で1つを印刷し、`--set` を省略すると1586枚すべてを印刷します。ウェブ画面の **ほんもののカード** も同じです。

エポック社は機械可読な一覧を公開していないため、バーコードは収集家が手元のカードを書き写した [wikiwiki.jp](https://wikiwiki.jp/barcode/) のページから取っています。各項目には出典ページの URL を記録しています。5件はチェックディジットが合いません。つまりどこかの桁が打ち間違いです。同じページには各カードの数値も載っていて、そのうち4件は、そのカードの本体でその数値として読める1桁の直し方が1つしかないため、その桁を直して印刷します。残る1件のガングラティは敵として載っていて、13けたはバーコードではなく数値そのものを並べたものです。HP 39600 はどのバーコードでも出せません。20000 を超える HP は 900 で終わる値しか読まれないからです。そのため、ほかの数値は同じで HP がいちばん近い 39900 になる 3996666425073 で印刷します。各カードに印刷される数値は wiki からの引き写しではなく、このプロジェクトのデコーダがバーコードから読み取ったものです。

6つのリストは初代バーコードバトラー向けです。最初のセット、魔強軍団ゴッドマーズ出現！、チューハイカーンの逆襲、最後の決戦ゴッドＶＳマザー、バーコードバトラーキャンデー、そして「バーコードバトラー対応」と書かれたコロコロコミックのおぼっちゃまくんのカードです。4つは特殊能力を初代の表で説明しています。ゴッドマーズのリストには数値がありませんが、IIだけが読む魔法使いも薬草やMPのアイテムもありません。正伝3 と 正伝4 はII²の7読みが必要で、正伝4 のカードの半分が7読みです。残りの24のリストはIIの表で印刷します。

ゼルダの伝説、小学二年生の特製カード、ストリートファイターII のカードは、[barcodebattler.co.uk](https://www.barcodebattler.co.uk/) の `deeta.js` にあるカードリストから取っています。英語で公開されているので、カード名も英語です。ゼルダの赤いくすりは、IIのボードゲームのカードでもあります。

ドラゴンスレイヤー英雄伝説、ドラえもん のび太の恐竜、おぼっちゃまくん、明治のカードはどこにも一覧がないため、[barcodebattler.co.uk が公開しているカードのスキャン](https://www.barcodebattler.co.uk/scans/Japan/)から1枚ずつバーコードを読み取り、表面に印刷された数値で名前と結び付けています。明治のカードは1番と5番しかスキャンされていません。

スーパーマリオワールドのセットと、アメリカとカナダでアーウィンが、イギリスとヨーロッパでトミーが売ったセットは、すべてのバーコードを文字で載せている [barcodebattler.co.uk](https://www.barcodebattler.co.uk/) のカードのページから取っています。トミーのカードはエポック社のコードにその国の名前を付けたもので、名前が違う版ごとにリストを分けています。イギリス、アイルランド、イタリアは同じ1つのリストで、ドイツ、スペイン、フランスはそれぞれいくつかのアイテムの名前を変えています。アーウィンのアメリカ版とカナダ版は名前もコードも同じで、カナダ版は英語の横にフランス語もあるだけなので、1つのリストです。アーウィンはアイテムとニュースのカード10枚すべてのコードを変えました。9枚は同じアイテムとして読まれ、ライフクリスタルは表面に数値ではなく「EP = ??」と印刷され、バーコードは300と読まれます。エポック社のカードは1600と印刷され、そのとおりに読まれます。

データック ドラゴンボールZ には40枚のカードが付属していました。[説明書](https://setsumei.cloudfree.jp/famicom/datachdragonballz/datachdragonballz.html)によると、スーパーサイヤ人孫悟空、スーパーサイヤ人トランクス、フリーザ（最終変身）、セル（完全体）などにはバーコードがなく、好きなバーコードを貼って使います。バーコードのある35枚と特別なスーパーサイヤ人孫悟空のカードの36枚を、エミュレータ [puNES](https://github.com/punesemu/puNES) のソースにある一覧から取り、1枚ずつ MAME 上のゲームで読み取ってから加えています。

このゲームは、バーコードの黒いバーと白いすき間の太さがそれぞれ3種類以上あるときだけ読み取ります。プログラムの $B085 で測った太さを種類ごとに分け、それより少ないと読み取りません。太さが1・2・4の3種類のバーコードは、通す速さによって読めたり読めなかったりします。このプログラムがゲーム用に作るバーコードはどの速さでも読め、`maeyomi decode --device dbz` はゲームが読まないバーコードを教え、スーパーマーケットは読めない商品に印を付けます。

## 2つの言語と絵

カードは画面の言語に関わらず、どの本体やゲーム用でも必ず英語と日本語の両方で印刷されます。バーコードバトラーIIのカードでは、生き物の種類、戦い方、3つの能力値、特殊能力、読み取り位置の案内、そのすべてが両方の言語で入ります。どの情報にも、まだどちらの文字も読めない子ども向けの絵が付きます。種類を示す色帯と絵記号、能力値のハートと剣と盾、そして特殊能力には何がどちらに変わるかを示す絵記号が入ります。たとえば「自分の攻撃が2倍」なら上向きの矢印が付いた剣です。意味を担うのは矢印の向きで、色ではありません。ほかのゲーム用のカードには、そのゲームが読む数値が、両方の言語の見出しと一緒に同じ色のタイルに載ります。J.リーグエキサイトステージ'94 の選手、データック バトルラッシュのパイロット、カットビロードの車のように、ゲームがかなだけで表示する名前は、英語の側では決まった規則でローマ字にします。画面の言語を切り替えると、メッセージや一覧もすべてその言語で描き直します。

バーコードバトラーIIの特殊能力の文言は両言語とも公開されているものです。日本語は barcodebattler.net/page05.htm からそのまま引用し、英語は同じページをこのプロジェクトが読み取ったものです。種族・職業・能力値の名称はこのプロジェクト独自の訳で、子どもが最初に習うひらがなとカタカナで書いています。プレイヤーが入力した名前は、どちらの文字でも入力どおりに印刷されます。

ウェブ画面は上部のボタンで英語と日本語を切り替え、選んだ言語を記憶します。

日本語はどの PDF リーダーにも入っているフォントで組んでいますが、埋め込みではなく参照です。印刷所に入稿する場合は PDF ではなく `--images png` で書き出したページ画像を送ってください。600dpi で、文字はすでに描画済みです。

## マウスがなくても、目が見えなくても

画面はキーボードだけで操作できます。スキップリンクで見出しを飛ばせ、6つのタブはタブ移動1回分にまとまっていて矢印キーで切り替わり、Home と End で両端に移動します。すべての操作部分にフォーカスの枠が表示され、どれも44×44ピクセル以上あり、食品の一覧はキーボードでスクロールできます。言語の切り替えは文書の `lang` も変えるので、スクリーンリーダーの読み上げも切り替わります。動きを減らす設定が有効な環境では、アニメーションを行いません。

axe-core は6つのタブすべてで、明るい配色でも暗い配色でも、WCAG 2.2 の A と AA に加えて独自のベストプラクティス規則についても違反を報告しません。規則では判定できない部分は実際のブラウザで手作業で確認しました。フォーカスの枠はスタイルシートではなくフォーカス中の要素から読み出して確認しました。

PDF には、構造ツリーなしで持てるものを入れてあります。各ファイルは自分の名前を持つので、読み上げソフトは `sheet.pdf` ではなく「Barcode Battler II card: Tea」と読み上げ、ファイル名よりその題名を優先するよう指定してあります。文書には言語・作成者・内容が宣言されています。カード上の文字はすべて実体のあるテキストです。名前、数値、特殊能力、両方の言語、バーの下の数字まで、すべてファイルから取り出せます。取り出される順序も人が読む順序で、まず種類、次に名前、各数値はそれが何を表すかのラベルの後、続いて特殊能力、最後にバーコードです。

入っていないものもあります。ReportLab はタグツリーを出力しないので、これらは PDF/UA ではありません。見出しもリストもなく、絵記号に代替テキストは付いておらず、日本語の部分に個別の言語指定もありません。絵記号は隣の文字が言っていることを繰り返しているだけなので、説明がなくても失われる情報はありません。検証ツールはこれらをタグなしと判定します。

## 色

カードは印刷所に出すことが多く、その場合は白黒で刷られることも珍しくありません。また渡す相手は子どもで、男の子のおよそ12人に1人は赤と緑を見分けません。どちらも測定で対処しています。

色だけで区別されるものはありません。どの色帯にも名前と絵記号があり、どの能力値にも固有の形と2文字のラベルがあるので、白黒で印刷したカードも色付きと同じことを伝えます。

計算は `src/maeyomi/rendering/colour.py` にあり、`tests/rendering/test_palette.py` が配色をその基準に照らします。

| 検査 | 基準 | 出典 |
|---|---|---|
| 色帯の上の白文字、カラーとグレースケールの両方 | 4.5対1 | WCAG 2.2 コントラスト最低基準 |
| タイル上の絵記号、カラーとグレースケールの両方 | 3対1 | WCAG 2.2 非テキストコントラスト |
| キャラクターの色帯どうし、通常の色覚と1型・2型・3型色覚 | CIE 1976 で20 | 2色が「同じ色の濃淡」ではなく「別の色」として読める距離 |
| キャラクターの色帯どうし、グレースケール印刷時 | 1.15対1 | 見分けのつく明度差 |
| 武器と防具の使い切り版と常設版、グレースケール時 | 1.5対1 | 絵記号が共通なので、明度がより多くを担う必要がある |

2色覚のシミュレーションは Brettel・Viénot・Mollon の線形近似を使っています。シートはラスタライズしてグレースケールに変換し、その上のすべてのバーコードをデコードしているので、色を一切出せないプリンタでも通用します。
